# 工程查看与结果复现

## 一、查看阶段成果

阶段报告保存在仓库根目录的 [开发过程记录.md](../开发过程记录.md)。该文件按当前阶段介绍设计过程，配图位于 `artifacts/screenshots/` 和 `artifacts/figures/`。

`artifacts/results/` 保存 82 组单元测试和 4 组原生测试电路的数值波形，以及汇总结果。`artifacts/iterations/v0/` 保存初版设计的尺寸和代表性失败证据；初版数据与最终版本分开存放。

## 二、重新分析已有波形

已验证的分析环境为 Python 3.12。建议建立独立环境，再安装依赖：

```sh
python -m venv .venv
```

Windows PowerShell 中运行：

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe scripts/check_all_cases.py
.venv\Scripts\python.exe scripts/finalize_stage1.py
```

Linux 中可使用 `.venv/bin/python` 执行相同命令。这一步只读取仓库中的波形，不调用 Cadence 或 PDK。

`check_all_cases.py` 检查读写保持状态、位线电压差、扰动前状态、扰动后恢复情况和注入电荷积分，生成 `stage1_checks.csv`、`stage1_checks.json`。`finalize_stage1.py` 独立检查四组原生测试结果，并生成读写保持图和 30 fC 扰动对比图。

最终扫描的预期汇总为 82 组中 68 组满足对应条件，14 组发生状态翻转。不能把“仿真正常结束”与“电路恢复成功”混为一谈。

## 三、在 Virtuoso 中打开工程

`cadence/rh_sram_lib/` 是本项目创建的 OpenAccess 库，包含以下单元：

| 单元 | 视图与用途 |
| --- | --- |
| `sram6t` | 基准单元的 schematic、symbol |
| `hphs12t` | 抗辐照单元的 schematic、symbol |
| `tb_sram6t_functional`、`tb_hphs12t_functional` | 读写保持测试原理图 |

在已有 Cadence 环境的 `cds.lib` 中定义 `rh_sram_lib` 的实际位置，同时定义课程提供的 `tsmc18rf` 工艺库。示例见 [cds.lib.example](../cadence/cds.lib.example)。工程库中不包含工艺器件的主库和模型文件。

| 工艺器件库 | `/home/rocky/work/iclab018um/tsmc18rf` |

测试电路使用的 PWL 文件在 `design/stimuli/` 中。原环境将它们放在 SRAM 工作目录的 `stimuli/` 下；迁移到其他机器时，需要相应调整电源激励的文件路径以及模型引用路径。

## 四、重新生成与仿真

以下流程需要已配置的 Virtuoso、Spectre 和工艺库。Windows 侧脚本通过已有 SSH 别名 `ic618` 连接课程虚拟机；密钥和 SSH 配置由使用者在本地设置。

1. 运行 `scripts/build_design.py`，生成器件定义、82 个测试用例和网表。
2. 运行 `scripts/generate_skill.py`，将生成的 `design/create_schematics.il` 放入虚拟机工作目录的 `scripts/` 下，再执行 `scripts/create_schematics.sh`。
3. 运行 `scripts/generate_testbenches.py`，将测试电路 SKILL 文件和激励复制到虚拟机，再执行 `scripts/create_testbenches.sh`。
4. 运行 `scripts/polish_schematics.py`，在虚拟机中执行生成的 SKILL 文件，为电路补充标注和主支路连线，并重新导出网表。
5. 运行 `scripts/sync_oa_netlists.py`，核对实际原理图导出的连接和尺寸，并更新最终仿真使用的 `design/netlists/bitcells.scs`。
6. 将 `design/netlists/` 中的文件放到虚拟机工作目录的 `netlists/`，将 `design/cases.json` 放到 `docs/cases.json`，再执行 `scripts/run_all_cases.sh`。
7. 执行 `scripts/run_native_testbenches.sh`，复核四个原生测试电路。将产生的波形复制回对应的 `artifacts/results/` 目录后，再运行本说明第二节中的分析脚本。

这组脚本按上述顺序配合使用，路径沿用原环境。迁移环境时应先调整路径；使用已保存的 OpenAccess 库只需按第三节配置库，无须重新生成原理图。
